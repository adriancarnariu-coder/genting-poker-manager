# Genting Poker Manager — rebuilt

New, independent application for the supplied Cardroom Magic Entries/Re-Entries reports. The previous application is preserved. No old browser data is migrated.

Run `node server.mjs` and open http://127.0.0.1:3001. Run `node --test test/*.test.js` for validation. All dependencies are vendored; no installation or network is needed for Excel processing.

Imports Forename + Surname, PlayerId, FlightName, ChipCount, Status and GDPR directly. A row with a positive ending ChipCount and no eliminated/withdrawn marker is a qualifier; Status Entered is valid. Zero stacks remain internally as nonqualifiers. Invalid chip counts on otherwise active records block export for source correction. An explicit Qualified column overrides the default classification. All imported records are retained; duplicate IDs/names are flagged, never merged.

Only literal Y or YES (case/outer whitespace ignored) permits full names. All other/missing/ambiguous GDPR fields use first/last whitespace-component initials. Source names, source name components and raw consent are retained in IndexedDB; public rows have only rank/name/nationality/flight/chips. No dates of birth, membership/card numbers or payment information are imported. Nationality needs a YES verification field; otherwise a dash. Staff confirms the operator publication policy before export. Initials remain pseudonymized personal data.

One upload accepts multiple XLS/XLSX files and runs parsing in a worker. File list supports replacement, removal and 30-second undo. Same-name reuploads replace the prior file. Every mutation recalculates ranks and totals, invalidates the previous JPEG and resets publication confirmation. IndexedDB revision checking prevents stale tabs silently overwriting a newer workspace.

One fresh canvas renders all qualifiers into one high-resolution JPEG, with fixed five-column order in every section and the user's official logo. No source filenames, IDs, GDPR fields or source image metadata are copied into the image. Supported irregular totals include 9, 29, 66, 79, 118 and 147.

Real-source integration check (local only): set GENTING_REAL_FIXTURES to the source directory then run tests. The supplied two reports yield 9 qualifiers, 6,905,000 chips, flight A. Private workbooks and actual player data are not included in this repository or deployment.

The current public column order is RANK, PLAYER NAME, FLIGHT, CHIP COUNT. Nationality remains internal only. Name/flight filters occupy table cells directly above their corresponding headers; they use only public rows and preserve global ranks. Filters never constrain the JPEG. REFRESH recalculates from already imported data, preserves filters/files, and invalidates the prior JPEG. Clear filters and shown/total counters are provided.


Chip-count search is a digit prefix filter over public numeric values. Commas, normal spaces and nonbreaking spaces are ignored; other characters produce a short validation error. The three filters combine without renumbering global ranks. JPEG generation continues to use the full public leaderboard, never the filtered result.


Excel validation recognizes OOXML ZIP, BIFF5/8 OLE and legacy raw BIFF signatures, and checks the workbook content after parsing. Required name/chip/flight columns and ambiguous GDPR mappings produce source-specific errors. Missing consent stays pseudonymized; full names are allowed only for Y/YES. Existing saved records retain their raw consent, so the new display rule applies without overwriting original data.

XLS report repair: FLT is recognized as Flight; original reports 1 d.xls and 1E.xls import 15 + 13 records (22,385,000 chips). Per the operator instruction, JPOT is now used as GDPR when GDPR/GDPR Consent is absent. Compatible HTML tables and SpreadsheetML XML exports with .xls extensions are read as inert workbook data, with UTF-8/UTF-16/Windows-1252 decoding and script/entity rejection. Source-specific errors preserve existing imports.


Consent provenance is retained as consentSources (original column names, indices, raw values), consentColumn and originalGdpr. Contradictory yes/no/unknown states across consent columns force initials and a source-row staff warning. GDPR columns take precedence over JPOT, including blank GDPR values. Pre-change imports without preserved raw consent remain initials and display a re-upload instruction; no source value is invented.

Flight display and search normalize explicit A-F, 1A/1 A, Day 1 A and Flight A labels to A-F, including already-stored records at public projection time. Imported originalFlight retains the raw source cell; existing records retain their unchanged flight field. Unknown flight labels display a dash, generate a source-row warning and block JPEG until corrected. Names, consent, chips, rank and source workbooks are unchanged.

Public display now uses QUALIFIED FROM and Day 1A-Day 1F. The existing public flight property contains the display label; source flight/originalFlight values stay untouched. Search normalizes A/1A/Day 1A/Day 1 A to the same exact flight so the letter A cannot accidentally match every Day label. JPEG gives the column 250 pixels and renders the same labels in every section.

Public columns are now RANK, PLAYER NAME, NATIONALITY, QUALIFIED FROM, CHIP COUNT. Nationality/Country/Country Code/CTY are read without country inference, flags, or synonym normalization. Original raw nationality, source columns and conflicts are retained. Only Y/YES consent without a consent conflict permits nationality; missing/placeholder/conflicting values display a dash. Search nationality filters only the public projection, combines with other filters and updates the white count; JPEG always uses the complete list. Existing saved nationality values use the same privacy rule; unavailable older data stays a dash until re-upload.

JPEG export now deliberately omits nationality. The interface and public search projection retain five columns; JPEG_COLUMNS declares only RANK, PLAYER NAME, QUALIFIED FROM, CHIP COUNT. The image renderer never draws nationality headers or values and redistributes the section width across four columns. All players and consent-safe names are exported regardless of active filters.

Staff display now uses staffRows: original full names and available non-conflicting nationalities are shown and searchable regardless of GDPR. JPEG generation exclusively uses publicRows with the existing consent rules, unaffected by staff filtering. Consent conflicts still force initials in the JPEG; nationality never enters the image. The staff note makes the different displays explicit. Existing source records remain in the same browser-local IndexedDB; no player data is uploaded or shared with other visitors.

The interface, accessibility labels, validation messages and workflow status text use British English (en-GB). This translation changes no imported values, source filenames, saved workspace data, GDPR rules or JPEG content.

Android import compatibility: the upload control is a directly tappable native file input with no restrictive accept filter. Workbook validation still requires XLS/XLSX and recognises the actual content. A bounded FileReader fallback and main-thread Excel reader handle unavailable file.arrayBuffer/workers, with per-file progress and explicit errors. Replacement uses an attached file input. Import failures do not replace existing files. If IndexedDB cannot open, a clearly labelled temporary session supports import/export without overwriting saved data. Phone controls have a 44px minimum touch height. QA: 32 tests, real XLS/XLSX, worker failure cases, browser multi-file XLS import and browser fallback XLSX import; no physical Android device was available.

Phone picker follow-up: use a visible native file input with explicit accept=*/*, retaining workbook extension/content validation in the importer. Phone-only Chrome launch link uses a user-initiated Android intent with the canonical HTTPS fallback, plus manual link instructions. File selection/cancellation status distinguishes a picker returning no document from an Excel parse error. No player data is sent by the Chrome link; workspaces remain browser-local. Verified visible-input XLSX import and narrow viewport; physical Android picker behaviour still requires device confirmation.

JPEG save actions: the same generated JPEG blob supplies preview, generic-named direct download, OPEN JPEG and a capability-gated native file-share action. Share cancellation and concrete errors are separate; no download-success claim is shown. Edits remove all stale actions; URLs already handed to a download/open action have a five-minute invalidation grace period. The Chrome link carries only the canonical application URL and instructs re-import/regeneration in that browser. QA: 38 tests, an actual desktop JPEG download with valid JPEG markers and UI invalidation; automated OPEN JPEG navigation was blocked by the browser testing security policy. No physical Android device was available.

Local session backup: SAVE BACKUP downloads a versioned staff-only JSON snapshot of imported source records and tournament details, without original Excel binaries, public JPEGs, policy approvals or server uploads. RESTORE BACKUP validates schema, sizes, IDs, numeric fields and raw source conflicts, previews counts, then replaces the workspace only on an explicit restore click. A prior-session rollback is stored atomically in the same IndexedDB transaction and survives reload; the next file change clears it. Tournament display uses the restored values, publication/duplicate confirmations reset and stale JPEG actions are invalidated. In temporary-session mode rollback is in memory, matching the existing storage warning. QA: 43 passing tests, actual download/re-import review, restore+undo across reload and malformed backup preserving 43 current players. Physical cross-device transfer remains user-mediated.

All viewer images and stale actions clear on invalidation. Chrome links use only the application URL and require import/restore/regeneration there.
